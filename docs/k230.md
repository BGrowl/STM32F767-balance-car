# K230 红球视觉扩展

[返回首页](../README.md)

## 分工

`K230_Part.py` 使用 CanMV K230 的摄像头、显示和串口 API。它在 K230 上识别红色区域、决定运动方向，通过串口向 STM32 下发动作；实时平衡仍由 STM32 完成。

本例使用 LAB 阈值与色块检测，没有训练模型、权重文件或距离估计。所谓推球，是车体朝目标前进，不包含独立踢球机构。

## 环境与部署

1. 准备支持 `media.sensor`、`media.display`、`media.media`、`machine.UART/FPIOA` 的 CanMV K230 固件。
2. 确认摄像头与显示硬件兼容。脚本使用 `Display.ST7701`、640×480 采集/显示；不同开发板需修改显示配置。
3. 按 [接线说明](hardware.md) 连接 GPIO40/41 和 STM32 PA10/9，共地，UART1 设置为 9600。
4. 先确认 STM32 单独平衡和串口控制正常，再通过 CanMV IDE 打开并运行 `K230_Part.py`。
5. 先架空或限定测试范围，调整 LAB 阈值和方向参数后再让车体接地运行。

原项目没有记录精确的 K230 板卡型号与固件版本，因此无法承诺所有 K230 固件直接兼容。桌面 Python 只能做语法检查，不能验证摄像头或显示 API。

## 程序流程

| 阶段 | 默认持续时间 | 动作 |
| --- | ---: | --- |
| WAIT | 0.5 s | 停止运动目标 |
| FORWARD | 4.5 s | 定时前进，尚未执行识球决策 |
| LANDING STOP | 1.0 s | 停止运动目标 |
| SET MID 0.2 | 0.5 s | 发送 `$5,...#`，将 STM32 中值改为 0.2° |
| BALL WAIT | 0.25 s | 等待后进入寻球 |
| 识球和对准 | 循环 | 连续检测确认后，居中则前进，偏左/偏右则转向 |
| 丢失目标 | 循环 | 短暂继续前进，再按上次位置搜索，之后默认向左搜索 |

检测图缩小为 320×240，取像素数最大的色块，连续 6 帧检出后确认。中间区域以检测图中心 ±60 像素判断。丢失后的保持时间为 0.35 s，定向搜索窗口到 1.2 s。

## 参数入口

| 参数 | 默认值 | 影响 |
| --- | --- | --- |
| `BALL_THRESHOLD` | `[(20,85,20,80,0,75)]` | LAB 红色阈值，须在实地光照下标定 |
| `MIN_BALL_PIXELS` | 120 | 最小色块像素数 |
| `MIN_BALL_AREA` | 100 | 最小色块面积 |
| `BALL_CONFIRM_FRAMES` | 6 | 连续确认帧数，不是固定秒数 |
| `DEADZONE` | 60 | 320 像素检测图上的居中范围 |
| `SEND_INTERVAL` | 0.25 s | 常规指令发送间隔 |
| `FORWARD_TIME` | 4.5 s | 识球前的开环前进时间 |

`PUSH`、`AIM LEFT` 和 `AIM RIGHT` 状态使用强制发送，会绕过 `SEND_INTERVAL` 并按每帧发指令。9600 波特率下应关注串口占用和处理负担。

## 已知限制

固定前进阶段没有避障；目标丢失后会继续搜索而非自动退出；颜色接近的背景可能被选中。`finally` 尝试发送停止命令并释放媒体资源，但拔线、断电、死机时无法保证该段执行，STM32 也没有可靠的失联停车机制。应先按真实环境缩短前进时间、标定阈值和中值，再进行整车测试。
